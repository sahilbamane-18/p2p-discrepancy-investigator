# Purchase-to-Payment Discrepancy Investigator

This project is a Python-based workflow for identifying financial exceptions between purchase orders (POs), delivery records, and supplier invoices. It is designed for finance and procurement teams who need to flag duplicate bills, quantity mismatches, and price variances before releasing payment.

## Business value

The tool helps teams:

- detect duplicate supplier invoices
- compare received quantity versus ordered quantity
- identify price variances from contract or PO baselines
- prioritize the most financially material cases for review
- export case data for downstream approval workflows

## Core features

- record matching across vendor, PO, and item
- tolerance-based discrepancy checks
- duplicate invoice detection
- financial impact calculation
- risk scoring and prioritization
- SQLite review queue for investigation tracking
- JSON export for integration with workflow tools

## Project structure

- `app/` — business logic, data models, and persistence
- `data/` — sample purchase orders, deliveries, and invoices
- `tests/` — validation tests
- `main.py` — entry point

## Quick start

1. Create a virtual environment:
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   ```

2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

3. Run the investigator:
   ```bash
   python main.py
   ```

4. Export a JSON report:
   ```bash
   python main.py --export-json output/report.json
   ```

5. Save cases to a SQLite review queue:
   ```bash
   python main.py --save-db
   ```

## Example discrepancy categories

- duplicate invoice detected
- quantity mismatch beyond tolerance
- price mismatch beyond tolerance
- missing PO or item reference
- invoice exceeds received quantity or agreed expected amount

## Sample output

The app prints a prioritized queue such as:

- Critical: duplicate invoice with high financial impact
- High: over-billed item or quantity variance above threshold
- Medium: moderate price variance
- Low: minor variance within tolerance but still flagged for audit trail

## Extending the project

This project can be evolved by:

- adding Excel uploads
- supporting supplier-specific tolerance profiles
- integrating ERP or AP system APIs
- creating a Streamlit dashboard for business users
- linking cases to approval and payment workflow states
